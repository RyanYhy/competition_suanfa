# 定位、导航修订与算法对比

本次已修正慢仿真下的指令超时判断，提供 AMCL / Cartographer 纯定位及 DWA / TEB 切换、统一路线测评，并实际运行了已安装 AMCL C++ 核心的离线对比。**尚无 Gazebo 在线对比结果，不能据此宣称某一算法已跑通或修好所有导航问题。**

## 1. 找到的问题与已做修改

读取了本机 ROS 日志 `~/.ros/log/aca8241e-c1f9-11f1-a865-79a60ce9649e/`：北灯前航点约耗时 24 秒墙钟、19 秒仿真时间；随后等待信号约 23 秒墙钟、16 秒仿真时间；北灯出口目标直到用户关闭前仍未完成。日志出现 12 次局部地图内找不到有效路径点、4 次 DWA 无可行轨迹，以及一次激光更新超时。这些是运行异常的证据，但没有同期真值轨迹，不能断定全部由 AMCL 引起。

已修改：

- **时钟一致性**：巡检原来按 0.3 秒墙钟判导航指令过期，控制器却按仿真时间运行；仿真变慢时可能误停车。现在指令和里程计主要按仿真时间检查，并保留 2 秒墙钟失联保护；时钟倒退和非有限值也拒绝执行。
- **DWA 到点和转向**：默认 `balanced` 档取消 XY 容差锁存，将朝向容差由 0.12 收紧到 0.06 rad；横向底盘使用零前置评分点，角速度采用奇数采样，使对称角速度窗口能够采到零转向。旧参数保留为 `baseline`。这些调整尚需动态验证。
- **减少视觉竞争**：OpenCV 默认单线程、最多每秒处理 5 帧，只在人员、车牌和信号观察阶段执行匹配；过灯期间保留信号检测。是否足够覆盖全部目标仍需实际巡检验证。
- **统一速度边界**：巡检输出按平移合速度、角速度和四轮可达轮速限制。DWA / TEB 通过同一个输出保护，默认最大合平移仍为 0.18 m/s。没有用提高限速掩盖堵转或定位误差。
- **可观测性**：新增 `/patrol/motion_guard`，说明是正常转发、无任务、导航指令过期、里程计过期、定位过期还是红灯停车。驱动器另发只供评测的 `/simulation/ground_truth`；真值不进入定位、规划或驱动闭环，也不发布 TF。

## 2. 实际完成的 AMCL 离线实验

直接链接系统的 `libamcl_sensors.so`、`libamcl_pf.so`、`libamcl_map.so`，调用实际 AMCL 粒子滤波、全向里程计和激光模型。不是自写近似算法，也没有冒充 Gazebo 实测。

用当前 world 的碰撞体在雷达高度连续射线求交，合成 720 束激光；参考栅格分辨率为 2 cm。沿 21 点路线生成 815 帧、6 Hz 输入，分别运行种子 11 / 22 / 33。激光噪声标准差 8 mm、丢点率 2%；人为注入前进里程计 +6%、横移 -12%、转向 +4% 的比例误差和小量随机噪声，初始位姿误差为 `(0.08 m, -0.06 m, 0.06 rad)`。统计跳过前 5 秒。

以下是三次实验各项指标的算术平均；P95 列为各次 P95 的平均：

| 配置 | 激光采样 / 粒子范围 | 位置 RMSE | 位置 P95 | 朝向 RMSE | 平均核心计算 / 输入帧 |
|---|---|---|---|---|---|
| AMCL baseline | 90 / 300–1500 | 3.450 cm | 5.724 cm | 0.661° | 0.779 ms |
| AMCL dense | 180 / 500–2000 | 3.446 cm | 5.824 cm | 0.560° | 2.358 ms |

增大采样量在这个场景没有带来明显的位置改善，耗时约为 3 倍，故保留 baseline 为默认。这里的耗时只包含滤波核心，不代表 ROS 节点、Gazebo 或完整导航实时率。三组种子也不足以证明普遍优劣；真实打滑、激光遮挡、地图失配和窄路控制均未由这个合成实验覆盖。

![AMCL 离线结果，非 Gazebo 实测](validation/localization_core/comparison.png)

[原始统计和场景哈希](validation/localization_core/summary.json)，同目录提供每次轨迹 CSV。种子 11 已另行复跑，除耗时外轨迹数值一致。复现命令（新目录保存，避免覆盖记录）：

```bash
source /opt/ros/noetic/setup.bash
cd ~/suanfa_ws/src
python3 smart_community_sim/tests/benchmark/run_amcl_core.py --output /tmp/amcl_core_repeat
```

## 3. 先比较现有 AMCL、DWA、TEB

在普通桌面终端关闭旧仿真和键盘节点，重新编译后启动，确保加载更新后的底盘插件：

```bash
cd ~/suanfa_ws
catkin_make
source devel/setup.bash
roslaunch smart_community_sim patrol.launch planner:=dwa
```

关闭后换 TEB：`roslaunch smart_community_sim patrol.launch planner:=teb`。默认仍开启相机识别和完整巡检要求。AMCL 密集参数可用 `amcl_profile:=dense`，旧 DWA 参数可用 `profile:=baseline`。

自动依次测试 AMCL 两组参数 × DWA / TEB，每组一轮：

```bash
rosrun smart_community_sim compare_navigation.py \
  --localizers amcl amcl_dense --planners dwa teb --repeats 1
```

默认结果保存在 `/tmp/community_comparison/日期_时间/`。正式对比建议 `--repeats 3`；比较旧/新 DWA 参数可加 `--profiles baseline balanced`。`--check` 只检查依赖和端口权限，不启动测量。

自动测评每次启动独立 ROS / Gazebo master、同一场景和同一 21 点路线。为隔离定位与规划的影响，**该模式关闭视觉、使用仿真信号灯话题；通过也不等于通过比赛视觉验收**。普通 `patrol.launch` 的视觉默认保持开启。

每次保存 `launch.log`、ROS 日志、`trajectory.csv` 和 `report.json`，总表为 `summary.json`。记录包括：

- 同一仿真时间戳的 Gazebo 真值、轮式里程计和 `map → base_footprint` 估计；位置 RMSE / P95 / 最大值、朝向误差。
- 全部航点到达时的真实距离和朝向误差；缺少任何航点均不能通过精度检查。当前工程诊断阈值为 5 cm / 5°，不是声称官方规定了该验收标准。
- 仿真耗时、墙钟耗时、实时率，导航阶段真实速度、规划速度、里程计速度、零指令比例及保护原因计数。
- 参数快照、场景哈希、丢弃和待同步样本数。至少 100 个有效样本且缺失比例小于 10% 才认为采样充分。

判断慢的来源：规划速度低先看路径、避障和到点行为；规划速度正常但 `/cmd_vel` 经常为零，查看 `motion_guard`；里程计速度正常而真值速度低，优先查车轮接触、打滑及电机参数；实时率低则整场仿真墙钟耗时增长。仅有轮式里程计无法证明底盘实际走得准。

`profile:=fast` 提供实验性上限：合平移 0.24 m/s、横移 0.18 m/s、转向 0.6 rad/s。它不是默认，也未验证停车距离和窄路通过性能。先运行已有 `drive_test.launch verify:=true` 检查实际驱动及制动，再做该档对比。

## 4. Cartographer 接入与同地图对比

Gmapping / Cartographer 建图与 AMCL 固定地图定位是不同任务。这里比较的是 **AMCL 固定地图定位和 Cartographer 冻结状态纯定位**，局部规划器另行选择。Gmapping 建图入口仍保留在 `mapping.launch`。

已加入 Cartographer 建图、状态保存、纯定位初始化、地图导出对齐。AMCL 和 Cartographer 互斥启动，编码器继续独占 `odom → base_footprint`。Cartographer 发布 `cartographer_map → odom`，已知起点提供静态 `map → cartographer_map`。这是坐标系锚定，不是运行时真值纠偏。

本机 `/opt/ros/noetic` 已有 AMCL 和 TEB，但没有可运行的 Cartographer；`~/catkin_ws_carto/src` 存在源码。实际尝试在 `/tmp` 配置其构建，首先失败在缺少 Abseil 的 `abslConfig.cmake`。因此这里没有 Cartographer 精度/速度结果，不能给出与 AMCL 的胜负结论。

可在具有系统安装权限和网络的桌面终端补齐该源码声明的依赖并构建（仍可能有后续依赖或版本问题）：

```bash
source /opt/ros/noetic/setup.bash
cd ~/catkin_ws_carto
rosdep install --from-paths src --ignore-src -r -y
catkin_make_isolated --install --use-ninja
source install_isolated/setup.bash
cd ~/suanfa_ws
catkin_make
source devel/setup.bash
```

必须从本比赛场景重新建状态文件，其他工作区已有 `.pbstream` 不能直接代用。关闭旧仿真，保留默认起点和朝向：

```bash
roslaunch smart_community_sim cartographer_mapping.launch
```

另开同样 source 环境的终端运行 `rosrun smart_community_sim keyboard_teleop.py`，覆盖道路和闭环。可在 RViz 以 `map` 为固定坐标系添加 `/cartographer/grid` 查看建图。停车、退出键盘后保存，保存操作会结束当前建图轨迹：

```bash
rosrun smart_community_sim save_cartographer.py /tmp/community_map.pbstream
```

同时产生 `.pbstream.json`，记录起点锚定和 world 哈希。为两种定位算法提供同一套规划地图，导出并转换到比赛坐标系：

```bash
rosrun cartographer_ros cartographer_pbstream_to_ros_map \
  -pbstream_filename=/tmp/community_map.pbstream \
  -map_filestem=/tmp/community_native -resolution=0.02
rosrun smart_community_sim align_cartographer_map.py \
  /tmp/community_native.yaml /tmp/community_map.pbstream.json /tmp/community_carto.yaml
python3 ~/suanfa_ws/src/smart_community_sim/scripts/generate_navigation_maps.py \
  --align-to-map /tmp/community_carto.yaml \
  --keepout-output /tmp/community_carto_keepout.yaml
```

对齐脚本会旋转和重采样实际栅格，避免仅修改 YAML 原点后仍与预设巡检点错位；它不能修复建图漂移。地图 YAML、PGM、状态及其 JSON 都要保留。关闭建图和仿真，再比较：

```bash
rosrun smart_community_sim compare_navigation.py \
  --localizers amcl cartographer --planners dwa teb --repeats 3 \
  --state /tmp/community_map.pbstream \
  --map /tmp/community_carto.yaml --keepout /tmp/community_carto_keepout.yaml
```

单独运行完整视觉巡检：

```bash
roslaunch smart_community_sim patrol.launch localization:=cartographer \
  state:=/tmp/community_map.pbstream \
  map:=/tmp/community_carto.yaml keepout_map:=/tmp/community_carto_keepout.yaml
```

自动比较使用默认起点 `(1.65, 1.75, 3.14159)` 建图。手动改变建图起点时，需要在纯定位 launch 同步传入 `anchor_x / anchor_y / anchor_yaw`；`x / y / yaw` 表示本次机器人起点，两组参数含义不同。初始化器检查保存的场景哈希与锚定参数，不一致会终止。

配置依据：[Cartographer ROS 坐标系选项](https://google-cartographer-ros.readthedocs.io/en/latest/configuration.html)、[纯定位说明](https://google-cartographer-ros.readthedocs.io/en/latest/going_further.html)。TF、纯定位服务和导出命令也与本机 Cartographer 源码核对过。

## 5. 验证边界

已完成插件编译、离线单元测试、AMCL 六次核心实验及一次种子复现；launch 分支和 Lua 配置做了离线解析检查。动态测试入口、采集和汇总已经实现，但执行环境对本地 `socket.bind` 返回 `Operation not permitted`，无法启动 ROS XML-RPC / Gazebo transport，不能继续获取本机在线数据。

可用性检查记录在 [navigation_preflight](validation/navigation_preflight/summary.json)；更新后的环境检查见 [navigation_preflight_final](validation/navigation_preflight_final/summary.json)。这些文件明确区分 `blocked`、`missing_dependencies`、`ready_not_run` 与真正 `measured`，不会把没跑的数据算成通过。

本次结论是：已修正明确的时钟问题并准备好可复现比较；离线实验不支持盲目增加 AMCL 粒子数。Cartographer / TEB 的实际效果、完整视觉巡检、到点精度、接触驱动和提速收益仍待有 ROS/Gazebo 运行权限的环境实测。
