# 紧凑人物布局与最新识别结果验证

2026-10-10。紧凑版曾有两轮自主巡航通过，后续复测发现人物类别波动，以本轮任务日志为准。当前为19点；历史实验记录仍保留在学习记录。

## 启动观看

关闭上一次场地/巡航，在新终端执行：

```bash
source ~/suanfa_ws/devel/setup.bash
LIBGL_ALWAYS_SOFTWARE=1 roslaunch --no-summary smart_community_sim patrol.launch gui:=true rviz:=true
```

自动沿正式路线执行一圈19航点。人物保留18块原尺寸立牌与原正面朝向，分别排成A北3/A西2/A南4/B北5/B东4紧凑小组；5个人物观察点，各观察一次、停留4秒。A南/B北原来重复的第二个观察点已撤去。模型仍为用户三个ONNX加PP-OCRv4，不以场景清单补人物或车牌。

RViz的Recognition显示带框图及中文类别；黄色框是待确认、绿色为已确认社区人员、橙色为已确认非社区人员。显示简称A1/B1等对应完整实例ID，类别和置信度分行避免紧凑排列时遮挡。带框图在观察/灯控阶段更新；全程相机用 `rqt_image_view /front_camera/image_raw` 查看。`/patrol/status` 为 `complete` 才表示本轮导航与识别完成。

## 固定结果目录

```text
smart_community_sim/validation/
├── 终端日志.log       本轮任务输出，末尾是任务汇总
├── 识别总览.jpg
└── yolo_images/       每个人物/车牌观察点一张最佳带框图；两处灯按识别颜色保留
```

[终端日志](../smart_community_sim/validation/终端日志.log)在运行中更新，每个识别点记录看到的人物/车牌/灯色和相应置信度，最后汇总A/B人数与类别、三牌、两路口、已到达航点和总状态。[YOLO图目录](../smart_community_sim/validation/yolo_images)单独放验证图片；[识别总览](../smart_community_sim/validation/识别总览.jpg)在结束或停止时更新，保留本轮真实图片和状态。尚无图片时显示明确的等待提示。

每次新启动或 `/patrol/start` 开始新巡航，自动清除上一轮生成图片、总览和日志，进度从0开始；不叠加时间戳目录，不生成任务MD/JSON。最佳图可被本轮更好画面替换。普通运行不保存轨迹、原图、裁剪或逐帧日志。目录所属标记放在目录外，内部仅三项；学习记录和历史研究实验不在清理范围内。

需要手动开始用 `autostart:=false`，然后 `rosservice call /patrol/start '{}'`。停止用 `rosservice call /patrol/stop '{}'`，退出用启动终端Ctrl-C。

终端用黄色突出 `[识别点结果]`、`[航点完成 4/19] A区北侧人物` 和最终通过提示，完整检测JSON不刷屏；异常仍提示。人物分数是该点实际帧中最终投票类别对应的YOLO峰值；车牌分开显示YOLO检测分数和确认帧OCR平均分数；灯色来自HSV和两帧稳定判断，显示的置信度属于YOLO灯箱检测，不能当作颜色概率。未确认候选明确标注，不能补作成功。

`终端日志.log` 保存巡航实际输出文本及运行期间ROS WARN/ERROR，移除颜色控制字符；启动器的进程启动/退出信息由ROS自身日志保留。末尾 `任务汇总` 包含未完成原因，失败也会写出；结束后不再追加迟到消息。航点完成表示到达并结束观察/等灯，整圈识别以最终状态为准。

启动命令中的 `--no-summary` 隐藏roslaunch的长参数清单，不影响任务提示。

专门调试时可加 `diagnostics:=true`，原图、裁剪、逐帧/事件及导航诊断另存 `doc/validation/识别调试结果/`，包内展示目录仍只有三项。普通观看无需此参数。导航旁路不把真值反馈给定位、规划或识别。代码修改后需重新启动节点才能生效。

## 自动整圈验收

关闭旧仿真，再执行：

```bash
source ~/suanfa_ws/devel/setup.bash
LIBGL_ALWAYS_SOFTWARE=1 roslaunch smart_community_sim vision_benchmark.launch
```

这是专用详细调试/验收入口，原始证据在 `doc/validation/识别调试结果/` 中保存 `raw_images/`、`plate_crops/`、`records/` 和 `navigation/`，结束后自动关闭仿真；三项展示结果仍在包内validation。可加 `gui:=true` 观看，或 `output:=/tmp/my_vision_debug vision_output:=/tmp/my_vision_display` 指定两个独立专用目录，二者不能嵌套。不能指向存有其他资料的目录。

运行结束后独立评估：

```bash
cd ~/suanfa_ws/src
python3 doc/validation/20261009_vision_live/evaluate_full_lap.py doc/validation/识别调试结果
```

它只在离线评估阶段读取场景快照与参考牌号，核对18人一一匹配、分类正确且无假确认轨迹；三牌在对应观察点各至少三张不同时间戳帧正确读字；全部19航点实际到点误差≤5cm/5°；实际车身不侵入岛区/外墙；两次实际绿灯入线。评估JSON写在独立调试目录，包内validation不会增加文件。

当前仍使用场地几何参考地图与lidar/custom定位规划；当前验收属于Gazebo场景，不代表实际SLAM建图或实车验收。人物门槛0.20、车牌0.35、灯箱0.50、OCR0.65，三帧确认与几何去重保留。几何关联适用于0.15m立牌，模型两类并不提供官方个人身份。

过程与失败证据见 [视觉学习记录](视觉识别学习记录.md)。视觉依赖见 `smart_community_sim/requirements-vision.txt`，当前环境已安装。
