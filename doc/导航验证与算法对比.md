# 导航验证与算法对比（2026-10-09）

这份文档记录当前工作区的真实 ROS/Gazebo 测试。过程和失败实验见 [导航修复学习记录](导航修复学习记录.md)。YOLO/OCR 尚未接入；诊断巡航不做人物或车牌识别验收。

## 如何复现

先退出旧 Gazebo、导航、建图及键盘控制，避免重复机器人或多个 `/cmd_vel` 发布者。编译一次：

```bash
cd ~/suanfa_ws
source /opt/ros/noetic/setup.bash
catkin_make -j4 -l4
source devel/setup.bash
```

运行一次完整的自动导航检查（关闭显示窗口）：

```bash
export LIBGL_ALWAYS_SOFTWARE=1
roslaunch smart_community_sim benchmark.launch output:=/tmp/community_check_$(date +%Y%m%d_%H%M%S)
```

如需看 Gazebo 车体，在该命令后加 `gui:=true`。基准测试关闭 RViz、视觉与规划器窗口，但仍保留激光、编码器、TF、实体碰撞和交通保护逻辑。它自动走 21 个点，结果目录包含 `report.json` 和 `trajectory.csv`；完成或失败后结束本次仿真。不可覆盖已有报告，因此每次使用不同 output 目录。

默认已采用用户提供的激光定位适配版与自定义规划器，显示默认关闭。对照 AMCL，仅替换定位参数：

```bash
roslaunch smart_community_sim benchmark.launch localization:=amcl planner:=custom output:=/tmp/community_amcl_check_$(date +%Y%m%d_%H%M%S)
```

显式指定默认算法为 `localization:=lidar planner:=custom`。局部规划器对照使用 `planner:=dwa` 或 `planner:=teb`。本机未安装 Cartographer ROS 可执行程序，当前不提供它的有效动态成绩。

手动在 RViz 指定目标（不含自动巡航的红绿灯保护）：

```bash
roslaunch smart_community_sim navigation.launch localization:=amcl planner:=custom gui:=true rviz:=true
```

## 验收哪些内容

- `report.json`：`passed_route`、`accuracy_pass`、`sufficient_samples` 都应为 true；21 个到点事件均应存在。
- 定位误差：对齐时间戳，比较 `map→base_footprint` 与 Gazebo 真实车体；不是只看轮子或 RViz 图标。
- 到点误差：实际车体与目标的距离不超过 5 cm、朝向误差不超过 5°。
- 几何边界：按 0.38×0.34 m 实际车身平面包络检查整个轨迹；不是只判断机器人中心在道路内。
- 灯色：诊断使用仿真信号灯状态和配置的周期，确认两处绿灯入场；不能称为相机灯色识别验收。

保存上述报告后，可生成图和附加边界报告：

```bash
python3 ~/suanfa_ws/src/doc/validation/20261009_navigation_live/plot_reports.py /tmp/本次结果目录
python3 ~/suanfa_ws/src/doc/validation/20261009_navigation_live/check_route.py /tmp/本次结果目录
```

附加报告 `route_safety.json` 中 `route_boundary_pass` 和 `signal_entry_pass` 应为 true。它是保存轨迹上的平面几何检测，不等同于精确三维碰撞接触验收。

## 当前地图和控制方式

目前使用 `field_reference.yaml`：根据比赛场地雷达高度的实体碰撞几何生成，属于已知场地地图。实际 Gmapping 采图已经运行，但初版有旋转、墙体重影，未通过导航验证；改进版也尚未验收。因此当前效果不能描述为“实际 SLAM 建图已完成”。

AMCL 和 jie_ware 都使用激光与地图定位。后者采用局部扫描匹配，没有 AMCL 粒子分布；对初始位姿有要求，不应假定它能自动从任意未知位置恢复。本场地由 launch 给出已知起点，重定位可以发送 map frame 的 `/initialpose`。

用户规划器从 `~/raicom_ws/src/my_local_planner` 复制到当前工作区作了适配：保留前视点与误差反馈，补全全向运动、终点控制状态、实例成员变量及预测车身碰撞检查，移除 OpenCV 窗口。jie_ware 原工作区同样保留；适配改动见两个包的 README。原包和适配版的成绩不能混用。

驱动继续使用有限力矩、真实滚子接触与轮轴角增量里程计。Gazebo 真值只进入测评，不进入定位或速度控制。小角速度下仍有接触停滞/突发问题；规划器的最低转向速度是一项针对当前底盘的控制措施，不能宣称底盘任意低速跟踪已经修好。

## 实测结果

同一参考/禁行图、同一 v2 自定义规划器、0.18 m/s / 0.5 rad/s 限速的定位对照：

| 定位 | 到点 | 最大到点位置 / 航向误差 | 定位 RMSE | 仿真耗时 | 边界 / 两处绿灯 |
|---|---|---|---|---|---|
| AMCL | 21/21 | 3.48 cm / 2.72° | 1.53 cm / 0.330° | 242.1 s | 通过 |
| jie_ware 适配版，首次 | 21/21 | 2.43 cm / 2.16° | 1.18 cm / 0.098° | 213.2 s | 通过 |
| jie_ware 适配版，最终默认复测 | 21/21 | 2.55 cm / 2.35° | 1.23 cm / 0.091° | 244.0 s | 通过 |

第一次激光组少等一轮信号灯，不能把约 30 秒的耗时差全算作算法优势。最终 AMCL/激光组运动段平移均速都约 0.138 m/s；此前 DWA 最多达到 19/21 点的失败运行约 0.11 m/s，这个对比不能替代相同成功路线的性能评测。

最终采用 `lidar/custom` 为默认；AMCL 保留为已通过的备选。显示窗口默认关闭，传 gui/rviz 参数可自行打开。编译与 38 项离线检查通过，底盘完整运动/停车/接地九项通过。实际 Gmapping 建图、任意低速跟踪和新版视觉仍有未通过/未验收项，详见学习记录。
